# Changelog

A running log of significant changes to this skills repo, newest first.

**Why this file exists:** the skills here are kept in sync with the live SkyCiv API. When an agent reads a
`SKILL.md` it sees the current state but not *what recently moved*. This log gives that context — which skills
changed, when, and why — so an agent can tell a settled convention from one that changed last week.

**Adding an entry:** one row per significant change, newest at the top. Keep *Details* to a sentence or two —
enough for an agent to know whether it needs to go and read the diff. Skip trivial commits (typos, formatting,
single-word tweaks). Use the skill folder name in *Skills Affected*, or `repo` for root-level files
(`README.md`, `CLAUDE.md`, `.github/copilot-instructions.md`).

| 2026-09-23 | Audited `load-combinations` against the live API and S3D UI; rewrote it as a single file | `load-combinations`, `s3d-api`, `run-quick-design`, repo | Removed `assets/`. Two of the four JSON examples put every wind direction in the same combination (`simultaneous` pattern), so their wind effects cancelled, and the Eurocode quick reference quoted the EQU `1.1G` set as the design set. They are replaced by compact factor tables taken from live generator runs for ASCE 7-22 LRFD **and ASD**, AS/NZS 1170.0 (**incl. NZ**), NBCC 2020, EN 1990 and IS 800. The `0.9D + 1.6L`-style `f`-filter combos are kept but labelled as generator variants rather than code combinations. **Corrections, all verified live:** `load_cases` must use the code's short symbols, because `"Dead: dead"` (which the skill told agents to use) shows every group as Dead in the UI; `load_combination_settings.country`/`code` are **not** inert, since they choose the standard the UI reads; `load_cases` adds `type: "load_case"` results to the solve and shifts later result ids; a flat `self_weight` or one without `load_group` defaults to `SW1` and **is** factored (both `load-combinations` and `s3d-api` said it wasn't); a combo without `SW1` applies no self-weight; omitted factors equal 0; unknown group keys are silently ignored; identical combos only warn. The generator's documented `"Please Select"` input **crashes**, as does a missing `multi_dropdown_1`. For NZ, the S3D UI's own request (captured live) sends `country_input: "australia"`, `standard_input: "AS-1170.0-2002"`, and passing `AS/NZS-1170.0-2002` there fails; the model and UI keep `AS/NZS-1170.0-2002` / `New Zealand`. `col6` takes explicit group names (`"D1,SW1"`), returned in `label`. Its real output is `combination_obj` (capitalised `criteria`). `run-quick-design`'s `7000-…` samples and schema are now real and working. Prototypes still use `"Dead: dead"` and still point at the deleted assets in comments; not yet updated. |
| 2026-09-22 | Audited `cloudcad-api` against the live API; restructured into `references/` + a helper script | `cloudcad-api`, `s3d-api`, `load-gen-api`, repo | Added frontmatter and a Gotchas section, and split element schemas, pages/title blocks and S3D mapping into `references/` (SKILL.md is now about 3.7k tokens, down from 11.5k). Added `scripts/cad_helpers.js` (builds page-wrapped drawings at any plot scale, generates revision-cloud arcs, lints for the silent failures) and a slim `assets/title-block-a2.json` with measured zones. Removed the 210 KB section library from both example exports. **Corrections, all verified by live render:** no `S3D.session.start` is needed; `create` accepts any payload with `status: 0`; `save` never returns `public_link`; `file.open` reports success even for missing files; revision clouds with `arcs: []` draw **nothing** (the skill said they auto-generate); hatch segments with `p1`/`p2` only **hang `create` to timeout**; omitting `projectionType` gives a correct **aligned** dimension (the skill said tilted dimensions were unsupported); text `alignment` anchors normally (no double shift); `block_instances.rotation` is **radians**; the old title-block safe zone **overlapped the title table**; `radiusDimensions` is `{center, radius, offsetPoint}`; images don't render inside blocks but tables, axes and dimensions do. New technique: a failing call returns `response.screenshot` of the headless editor, which is used to verify renders. Also fixed the dead `skyciv-core` prerequisite link in `s3d-api`/`load-gen-api`, and stale `SKILLS.md` references in `prototypes/`. |
| 2026-09-22 | Audited `baseplate` against the live API; split per-code data into `references/` | `baseplate`, repo | Added frontmatter, a Gotchas section and per-code `references/<code>.md` files (materials, diameters, electrodes, `factors`), loaded only for the chosen `design_code`. Corrections, all verified live: the old minimal example **failed** (`Pipe`/`PIPE 6 STD` → `Pipes`/`Pipe6STD`); **Canadian diameters are imperial sizes in mm** (`12.7`, `15.9`, `19.1`, `22.2`) and the documented `12/16/20` are silently ignored; Australian base plate grades are `AS/NZS 3678`/`1594`/`3597`, not the column list. New behaviour documented: invalid strings silently fall back to defaults with `status: 0`; a failing `detailing` check or non-zero `My` **hangs to the ~45 s timeout** (not extendable via `options.timeout`); a `fixed` base needs `Mz ≠ 0` in every case; failures report reasons in `conflicts`; `lc_number` is the 1-based position in `loads`; `capacity: 0` means not evaluated; `status: 0` doesn't mean the design passes. The S3D-reactions section no longer suggests `result_filter` and now points to `analysis-results` with a sign check. `sample-api/` files unchanged (re-run, results identical). |
| 2026-09-21 | Corrected four `analysis-results` schema claims | `analysis-results`, `s3d-apps`, repo | All four verified against the reference solve, and all four were shapes an agent would get wrong silently. **Station values are not always floats** - at a discontinuity a station holds a 2-element `[left, right]` pair (2,254 of them across the reference solve), so `Math.max(...Object.values(series))` returns `NaN` rather than throwing. **`plate_element_forces`/`_stresses` are absent, not `{}`**, on `user_defined` combinations, so reading them unguarded throws. **Station count varies per member** and is not `settings.evaluation_points` - read `member_stations["<id>"].length`. And `S3D.results.getAll(true)` inside the callback reads the local cache rather than re-downloading, so the example and the warning no longer contradict (same snippet fixed in `s3d-apps`). Also added `name`/`description` frontmatter for discovery. `assets/make-shape.py` is a **maintainer tool** that re-verifies the whole 5.6 MB asset and found three of the four errors; its output is gitignored and agents should not run it - the SKILL.md tables carry everything it finds at a third of the tokens. |
