# Changelog

A running log of significant changes to this skills repo, newest first.

**Why this file exists:** the skills here are kept in sync with the live SkyCiv API. When an agent reads a
`SKILL.md` it sees the current state but not *what recently moved*. This log gives that context — which skills
changed, when, and why — so an agent can tell a settled convention from one that changed last week.

**Adding an entry:** one row per significant change, newest at the top. Keep *Details* to a sentence or two —
enough for an agent to know whether it needs to go and read the diff. Skip trivial commits (typos, formatting,
single-word tweaks). Use the skill folder name in *Skills Affected*, or `repo` for root-level files
(`README.md`, `CLAUDE.md`, `.github/copilot-instructions.md`).

| 2026-09-22 | Audited `baseplate` against the live API; split per-code data into `references/` | `baseplate`, repo | Added frontmatter, a Gotchas section and per-code `references/<code>.md` files (materials, diameters, electrodes, `factors`), loaded only for the chosen `design_code`. Corrections, all verified live: the old minimal example **failed** (`Pipe`/`PIPE 6 STD` → `Pipes`/`Pipe6STD`); **Canadian diameters are imperial sizes in mm** (`12.7`, `15.9`, `19.1`, `22.2`) and the documented `12/16/20` are silently ignored; Australian base plate grades are `AS/NZS 3678`/`1594`/`3597`, not the column list. New behaviour documented: invalid strings silently fall back to defaults with `status: 0`; a failing `detailing` check or non-zero `My` **hangs to the ~45 s timeout** (not extendable via `options.timeout`); a `fixed` base needs `Mz ≠ 0` in every case; failures report reasons in `conflicts`; `lc_number` is the 1-based position in `loads`; `capacity: 0` means not evaluated; `status: 0` doesn't mean the design passes. The S3D-reactions section no longer suggests `result_filter` and now points to `analysis-results` with a sign check. `sample-api/` files unchanged (re-run, results identical). |
| 2026-09-21 | Corrected four `analysis-results` schema claims | `analysis-results`, `s3d-apps`, repo | All four verified against the reference solve, and all four were shapes an agent would get wrong silently. **Station values are not always floats** - at a discontinuity a station holds a 2-element `[left, right]` pair (2,254 of them across the reference solve), so `Math.max(...Object.values(series))` returns `NaN` rather than throwing. **`plate_element_forces`/`_stresses` are absent, not `{}`**, on `user_defined` combinations, so reading them unguarded throws. **Station count varies per member** and is not `settings.evaluation_points` - read `member_stations["<id>"].length`. And `S3D.results.getAll(true)` inside the callback reads the local cache rather than re-downloading, so the example and the warning no longer contradict (same snippet fixed in `s3d-apps`). Also added `name`/`description` frontmatter for discovery. `assets/make-shape.py` is a **maintainer tool** that re-verifies the whole 5.6 MB asset and found three of the four errors; its output is gitignored and agents should not run it - the SKILL.md tables carry everything it finds at a third of the tokens. |
| 2026-09-20 | New `build-quick-design-calculator` skill | `build-quick-design-calculator`, repo | Authoring skill for SkyCiv Quick Design calc packs (`config.json`, `calculate.js`, `ui.js`, `docs.md`, `s3d_integration.js`). Covers the input-form schema, the server-side globals (`REPORT`, `ReportHelpers`, `SectionProps`, `Database`, `requireUtil`), the results/utility-box object, metric/imperial conversion and S3D batch integration. The 21 official Quick Design docs are bundled under `assets/documentation/`. This is the **authoring** counterpart to `run-quick-design`, which only *calls* published calculators by UID. |
| 2026-09-20 | New `skill-writer` meta-skill | `skill-writer` | Skill for authoring and auditing other skills against the [Agent Skills spec](https://agentskills.io/specification) — frontmatter rules, description writing, progressive disclosure, plus this repo's own conventions. Ships `scripts/validate_skill.py` (frontmatter, naming, ~5000-token body limit, dangling references) and two SKILL.md templates. Run the validator on any skill before shipping it. |
